# Точка выхода на Cloudflare Workers

Бесплатный тариф, регистрация по почте, **карта не нужна**. Это и есть
ответ на главное препятствие проекта: где взять узел за границей, не
арендуя его.

## Что нужно

Аккаунт Cloudflare и Node.js. Больше ничего.

## Порядок

```bash
cd clients/worker

# 1. Придумать секрет и идентификатор пользователя.
node -e '
  const b = crypto.getRandomValues(new Uint8Array(32));
  const b64 = Buffer.from(b).toString("base64url");
  console.log("секрет:", b64);
  console.log("uuid:  ", crypto.randomUUID());
'

# 2. Развернуть.
npx wrangler deploy

# 3. Положить секреты (значения из шага 1).
npx wrangler secret put ATLAS_SECRET
npx wrangler secret put ATLAS_UUID
```

Идентификатор берите **из шага 1**, а не из примера в документации.
На пути `/` он единственное, что отделяет ваш край от постороннего:
кто угадает поддомен и подставит известный UUID, тот получит рабочий
прокси за счёт вашей квоты.

`wrangler deploy` напечатает адрес вида
`https://atlas-edge.ваш-поддомен.workers.dev`.

## Два режима

| Путь | Кто говорит | Что даёт |
|---|---|---|
| `/` | Happ, Hiddify, v2rayNG — любой клиент | обычный VLESS поверх WebSocket |
| `/e` | только наш клиент | плюс сквозной канал: посредник между телефоном и Cloudflare ничего не получит |

Выбор по пути, а не угадыванием по первым байтам: угадывать — значит
однажды принять чужое приветствие за своё.

Обычный режим слабее по скрытности: она держится только на TLS самого
Cloudflare. Зато он работает с тем, что человек уже поставил из App
Store, — а приложение, которого нет, не защищает никого.

## Ключ доступа

```
vless://UUID@atlas-edge.ваш-поддомен.workers.dev:443?type=ws&security=tls&path=/&host=atlas-edge.ваш-поддомен.workers.dev&fp=chrome#atlas
```

Вставляется как есть в Happ, Hiddify или v2rayNG — они дадут системный
VPN на всём устройстве, включая приложения и сотовую связь.

Для нашего клиента путь меняется на `/e`, и добавляется `&edge=СЕКРЕТ`:
это наше расширение, чужие клиенты его не понимают.

## Сайты за Cloudflare: нужен `ATLAS_PROXY_IP`

Самая заметная неожиданность этого яруса, и лучше узнать о ней здесь,
чем гадать над неоткрывающимся сайтом.

> **Cloudflare запрещает Worker'у соединяться с адресами самой
> Cloudflare.** Для платформы это петля.

За Cloudflare стоит немалая часть интернета — и `claude.ai` в том
числе. Выглядит это так: туннель поднят, скорость отличная, YouTube и
Telegram открываются, а несколько сайтов не открываются никогда.
Причина не в блокировке и не в ТСПУ, и по симптому её не угадать.

Обход — промежуточный узел, до которого Worker'у ходить не запрещено:

```bash
npx wrangler secret put ATLAS_PROXY_IP     # адрес или адрес:порт
```

Край пробует соединиться напрямую и переключается на посредника
**только при отказе** — то есть обычный трафик через него не идёт.
Значений можно перечислить несколько, через запятую.

> **Честная оговорка, без которой настройка вводит в заблуждение.**
> Посредник обязан пересылать байты **прозрачно**. Оба проверенных
> публичных узла этого не делают: они сами завершают рукопожатие своим
> сертификатом, и клиент получает ошибку проверки имени вместо сайта.
> Перебор списка тут не спасает — край останавливается на первом узле,
> принявшем соединение по TCP, а негодный принимает его прекрасно.
> Отличить их край не может: разница видна только клиенту и только по
> сертификату. Измерено: 0 из 8 с обоими узлами.
>
> То есть настройка работает ровно тогда, когда у вас есть **свой**
> прозрачный узел. Если его нет, сайты за Cloudflare на этом ярусе
> недоступны, и честнее знать это сразу, чем перебирать чужие адреса.

Умолчания нет намеренно. Зашитый в код чужой адрес означал бы, что
трафик пользователей молча уходит через узел, которого они не выбирали.
Посредник пересылает байты как есть, поэтому TLS остаётся сквозным от
устройства до сайта: ему видно имя в `ClientHello` и объём, но не
содержимое. Это ровно тот же уровень доверия, что и к любому транзитному
провайдеру, — но выбрать его должны вы, а не мы.

## DNS

Клиент в режиме системного VPN шлёт запросы имён в туннель командой
UDP. Край отвечает на них сам, отправляя запрос по HTTPS
(`https://cloudflare-dns.com/dns-query`, меняется через `ATLAS_DOH`).

Датаграмм наружу край послать не может — `connect()` даёт только TCP, —
поэтому UDP принимается **только** для порта 53. Для всего остального
он по-прежнему отказывает, и это не упущение: отправить такой пакет
нечем.

## Что здесь честно сказать

**Cloudflare видит ваш трафик.** Край обязан знать, куда соединяться,
иначе он не соединится. Сквозной канал закрывает посредника между
телефоном и Cloudflare — то есть ТСПУ, — но не саму площадку. Обещать
приватность от Cloudflare было бы враньём.

**Условия использования — серая зона.** Бесплатный тариф не задуман под
проксирование. Заводите отдельный аккаунт, потеря которого ничего не
рушит.

**Скорость ниже, чем у своей машины.** HTTP-обрамление, ограничения на
длительность соединения, лимиты бесплатного тарифа.

## Согласие двух реализаций

`src/edge.js` описывает тот же протокол, что `core/atlas-transport/src/edge.rs`.
Два описания одного протокола расходятся всегда, поэтому согласие
проверяется настоящим прогоном: `core/atlas-transport/tests/interop.rs`
поднимает эту сторону узлом и сверяет байты в обе стороны.

Правка здесь без правки там уронит сборку. Так и задумано.
