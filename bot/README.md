# Бот Gloria VPN

Запускается на машине, где стоит панель. Там уже есть Docker, PostgreSQL и
Caddy, и туда же бот ходит за ключами — все обращения остаются внутри
машины.

## Из чего собран

| Крейт | За что отвечает | Чем проверен |
|---|---|---|
| `atlas-bot` | экраны, кнопки, тексты, витрина | обычными тестами |
| `atlas-panel` | выдача и продление в Remnawave | обычными тестами |
| `atlas-store` | заказы, платежи, подписки | живым PostgreSQL |
| `atlas-tg` | разбор обновлений и отправка | обычными тестами |
| `gloria` | соединение проводов | только запуском |

Ни один крейт, кроме `gloria`, не ходит в сеть: они собирают запросы и
разбирают ответы. Поэтому ошибка в разборе ловится тестом, а не подбором
на живом сервисе.

## Что нужно задать

Переменные окружения. Секреты сюда, в репозиторий, **не попадают**.

| Переменная | Обязательна | Что это |
|---|---|---|
| `GLORIA_BOT_TOKEN` | да | токен от @BotFather |
| `GLORIA_PANEL_URL` | да | адрес API панели, см. ниже |
| `GLORIA_PANEL_TOKEN` | да | Remnawave → API-токены |
| `GLORIA_DATABASE_URL` | да | `postgres://gloria:ПАРОЛЬ@127.0.0.1:6767/gloria` |
| `GLORIA_SQUADS` | да | UUID отрядов через запятую |
| `GLORIA_ADMINS` | нет | ваш номер в Telegram |
| `GLORIA_SBP_PHONE` | нет | номер для перевода по СБП |
| `GLORIA_SBP_NAME` | нет | имя получателя, как его покажет банк |

Бот отказывается стартовать, если чего-то обязательного нет, и **называет
переменную по имени**. «Что-то не настроено» в четыре часа ночи — это час
поисков.

Без `GLORIA_SBP_*` бот работает, но на счёт отвечает «приём оплаты ещё
настраивается, напишите в поддержку». Без `GLORIA_ADMINS` подтверждать
оплаты будет некому.

Где взять UUID отряда: панель → Internal Squads → нужный отряд, его
идентификатор в адресе страницы.

### Адрес панели — петлевой, а не публичный

`GLORIA_PANEL_URL` — это `http://127.0.0.1:3000`, а **не** тот адрес, по
которому вы открываете панель в браузере.

Панель за Caddy закрывает `/api/*` от внешнего мира: по публичному адресу
запрос упирается в `404` при живом и совершенно правильном токене. Это
намеренно — так панель не подтверждает наличие API тому, кто его щупает.

Бот стоит на той же машине, и панель публикует API на петлю. Обращение
туда не выходит наружу вовсе и не зависит от чужих настроек Caddy.

`http` здесь допустим ровно поэтому: требование `https` существует ради
того, чтобы токен панели не шёл по сети открытым, а по `127.0.0.1` он по
сети и не идёт. Для любого другого имени бот по-прежнему требует `https`,
и проверка смотрит на начало адреса — `http://127.0.0.1.чужое.example`
петлевым не считается.

Порт уточните по `docker ps`; у публикующего API контейнера это обычно
`127.0.0.1:3000`.

### Порт базы

Порт базы в `GLORIA_DATABASE_URL` — **не 5432**. Панель публикует свой
PostgreSQL на другой порт хоста; какой именно, показывает
`docker ps --format '{{.Names}}   {{.Ports}}'` слева от стрелки (обычно
`127.0.0.1:6767`). Подробнее — в `db/README.md`.

## Как запустить

```bash
# 1. Компилятор C. Rust линкует через cc, и у части зависимостей (libc,
#    ring, typenum) есть скрипты сборки. На свежей Ubuntu их нет, и сборка
#    падает на «error: linker `cc` not found».
apt-get update && apt-get install -y build-essential pkg-config

# 2. База — если ещё не создана, см. db/README.md
# 3. Сборка
cd bot && cargo build --release

# 4. Настройки
cat > /etc/gloria.env <<'ENV'
GLORIA_BOT_TOKEN=…
GLORIA_PANEL_URL=https://panel.…
GLORIA_PANEL_TOKEN=…
GLORIA_DATABASE_URL=postgres://gloria:…@127.0.0.1:6767/gloria
GLORIA_SQUADS=…
GLORIA_ADMINS=…
ENV
chmod 600 /etc/gloria.env

# 5. Проверка вручную
set -a; . /etc/gloria.env; set +a
./target/release/gloria
```

При успехе печатается строка вида
`Бот запущен. Config { bot_token: "<скрыт>", … }` — секреты в неё не
попадают намеренно: вывод уходит в журнал, а журнал читают и пересылают.

## Службой

```ini
# /etc/systemd/system/gloria-bot.service
[Unit]
Description=Gloria VPN bot
After=network-online.target docker.service

[Service]
EnvironmentFile=/etc/gloria.env
ExecStart=/opt/gloria/gloria
Restart=always
RestartSec=5
User=gloria

[Install]
WantedBy=multi-user.target
```

```bash
systemctl enable --now gloria-bot
journalctl -u gloria-bot -f
```

## Что умеет сегодня

**Покупатель.** `/start` включает пробные три дня сразу, без кнопок и
запросов: каждый шаг между «зашёл» и «работает» теряет часть людей. Дальше
меню — подписка, продление, подключение, помощь. Выбор тарифа выставляет
счёт на **уникальную сумму**, по которой платёж потом узнаётся.

**Владелец** (кто указан в `GLORIA_ADMINS`):

```
/pending      открытые счета: сумма, тариф, кому
/ok 198.99    подтвердить платёж по сумме
```

Повторное `/ok` по тому же счёту ничего не меняет — проверено тестом:
нажать дважды, не заметив, легко.

## Как дата попадает в панель

Не прямым вызовом после оплаты, а очередью. В базе рядом с нашей датой
лежит `panel_expires_at` — та, которую панель подтвердила. Разошлись —
значит есть работа; бот разбирает её на каждом круге цикла, то есть не
реже раза в полминуты.

Прямой вызов после оплаты теряется при обрыве связи ровно в тот момент,
когда деньги уже взяты. Очередь при обрыве просто остаётся непустой.

Гасить просроченных не нужно: панель меняет статусы сама по своей дате —
у неё для этого есть собственные события `user.expired`, `user.disabled`.
Наша забота одна: чтобы её дата совпадала с нашей.

Отметка о согласовании ставится **той датой, которую отвозили**. Если
между чтением очереди и ответом панели человек оплатил ещё раз, отметка
не применится и строка останется в очереди — иначе продление пропало бы
молча.

## Чего пока нет

- **Автоматического приёма оплаты.** Ждём одобрения ЮKassa; адаптер к ней
  написан и проверен, подключается настройкой.
- **Напоминаний об окончании.** Таблица под них есть, рассылки нет.
- **Криптоканала.** Спроектирован в `docs/17-payments.md`.
- **Реферальных начислений.** Экран в мини-приложении есть, начислений нет.

## Проверка при разработке

```bash
cd bot
cargo test                                   # без базы: часть тестов пропускается
GLORIA_TEST_DATABASE_URL=postgres://postgres@127.0.0.1/gloria_test cargo test
```

Если переменная задана, а база недоступна, тесты **падают**, а не
пропускаются: иначе «зелёный» означал бы «не проверено».
