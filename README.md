# ATLAS

**Adaptive Transport Layer & Anti-censorship System**

Свободная, бесплатная и децентрализованная система обхода сетевой цензуры для iOS, Android, Windows, macOS и Linux.
Без арендованных серверов. Без платных подписок. Без централизованной инфраструктуры.

> Фаза 1 в работе. Готовы шесть крейтов ядра: типы и разбор ключей, гибридная криптография,
> **работающий клиент TLS 1.3** с постквантовым обменом ключами, кодек VLESS с XTLS-Vision,
> метка REALITY, WebSocket. 328 тестов, сборка под семь платформ.
> Клиент проверен на живых серверах: 19 из 20 узлов, включая российские.
> Известные слабые места — [docs/11-weaknesses.md](docs/11-weaknesses.md).

## В чём идея

Обычный бесплатный VPN умирает от арифметики: чем больше пользователей, тем дороже инфраструктура и тем проще её заблокировать — она централизована и конечна.

ATLAS переворачивает эту логику:

> **Приложение автоматически разворачивает точку выхода на бесплатном аккаунте самого пользователя — и опционально делится ею с сетью.**

Получается система, у которой **стоимость инфраструктуры равна нулю**, а **устойчивость растёт вместе с числом пользователей**: точек выхода столько же, сколько людей, они разбросаны по тысячам независимых аккаунтов у десятка провайдеров, и перечислить их противнику практически невозможно.

Плюс к этому — режим, в котором **точка выхода вообще не нужна**: DPI-десинхронизация обходит блокировку конкретных сайтов прямо на устройстве, без единого промежуточного узла.

### Никаких покупных ключей

ATLAS **не требует вставлять ключ** (`vless://`, `vmess://` и подобные), чтобы работать. Такие ключи обычно продают — и это ровно та зависимость, от которой проект избавляется.

Учётные данные берутся из трёх источников, и ни один из них не покупается:

1. **Приложение генерирует их само** — при развёртывании твоей точки оно создаёт пару X25519, идентификатор и `shortId`, подбирает домен прикрытия и заливает конфиг. Ты не видишь ни одного ключа.
2. **Каталог сети** — подписанный дескриптор, полученный по анонимному креденшелу.
3. **Импорт чужого URI** — только для совместимости и чтобы поделиться своей точкой с близкими. Не обязателен никогда.

Разбор чужих схем в проекте есть по двум причинам: их устройство надо знать, чтобы строить своё (см. [01-protocols.md](docs/01-protocols.md)), и пользователь должен иметь возможность экспортировать **свою** точку одной ссылкой или QR-кодом.

## Ключевые технические решения

| | |
|---|---|
| **Базовый транспорт** | VLESS + REALITY + XTLS-Vision — единственная схема, устойчивая к активному зондированию ТСПУ |
| **Полиморфизм** | 10+ транспортов, автовыбор через контекстный многорукий бандит (Thompson sampling), а не через настройки |
| **Детект тротлинга** | Миграция при деградации скорости, а не только при обрыве — ТСПУ чаще душит, чем рвёт |
| **Нулевая инфраструктура** | Шесть ярусов: от DPI-десинхронизации без сервера до волонтёрского WebRTC-mesh |
| **Криптография** | Гибрид классика + постквант: Ed25519 + ML-DSA-65, X25519 + ML-KEM-768. В TLS — `X25519MLKEM768`, проверено на живых серверах |
| **Каталог точек** | Подписанный append-only Merkle-лог с gossip по 8 независимым каналам |
| **Раздача точек** | Lox-подобные анонимные креденшелы — противник не может перечислить сеть, даже установив приложение |
| **Ядро** | Rust (лимит памяти iOS Network Extension — 50 МБ, GC там не выживает) |
| **Приватность** | Нет регистрации, нет серверной базы пользователей, телеметрия только opt-in и с шумом |

## Принятые решения

**Ядро — своё, на Rust.** Xray и sing-box не встраиваются. Плата за это — риск разойтись с браузером по отпечатку, поэтому сверка JA4 с эталоном Chrome стоит в CI и роняет сборку при расхождении в одном символе. Подробно — [02-architecture.md](docs/02-architecture.md) и [08-fingerprint-calibration.md](docs/08-fingerprint-calibration.md).

**iOS — два варианта из одной кодовой базы.** `lite` работает под LiveContainer с бесплатным Apple ID на актуальных iOS и забирает системный трафик Wi-Fi через `.mobileconfig` с PAC; `full` с `NEPacketTunnelProvider` требует TrollStore или платного аккаунта. Deployment target — iOS 14.0. Почему именно так — [05-clients.md](docs/05-clients.md).

## Состояние ядра

| Крейт | Что делает | Готовность |
|---|---|---|
| `atlas-types` | Модель протокола, транспорта и маскировки; разбор и построение ключей всех схем; проверка смысловых ошибок | ✅ |
| `atlas-crypto` | Ed25519 + ML-DSA-65, X25519 + ML-KEM-768, BLAKE3; генерация учётных данных для своих точек | ✅ |
| `atlas-tls` | `ClientHello` с отпечатком Chrome 141, JA3/JA4, сверка с живым захватом; полный клиент TLS 1.3 — расписание ключей и слой записей по следу RFC 8448, `X25519MLKEM768`, `HelloRetryRequest`, ALPS, сжатый сертификат, смена ключей | ✅ |
| `atlas-vless` | Кодек VLESS: заголовки, addons, обрамление UDP, паддинг XTLS-Vision | ✅ |
| `atlas-reality` | Метка REALITY внутри `session_id`, обе стороны; приёмка сервера по общему секрету вместо цепочки сертификатов; защита от повтора; совместимость с Xray 26.3.27 проверена | ✅ |
| `atlas-transport` | WebSocket: рукопожатие и кадры (нужен для яруса T1) | ✅ ws, XHTTP далее |
| `atlas-probe`, `atlas-strategy` | Разведка сети и выбор стратегии | далее |
