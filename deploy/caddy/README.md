# Caddy

Конфиг Caddy живёт на сервере и в репозитории до сих пор не хранился. Это
та же беда, что была с настройками панели: при переустановке машины он
набирается заново по памяти — и не набирается.

Здесь пока одна часть, которой нам не хватило при разборе поломки.

## Зачем журнал обращений

Правила ответов подписки (`deploy/remnawave/response-rules.json`) устроены
так: Happ и INCY получают адреса, все остальные — `403`. Правило опознаёт
клиента по строке `User-Agent`.

Из этого следует неприятное свойство: **клиент, чью строку мы не угадали,
получает отказ молча.** У человека просто не обновляется подписка, а в
панели ничего не видно — она не показывает, кто приходил и что получил.

Правило для INCY было написано по предположению («строка содержит `incy`»)
и на живом INCY не проверялось. Проверены были только два случая: голый
`curl` получает `403`, `curl -A 'Happ/1.0'` получает `200`.

Журнал закрывает этот пробел: в нём видно, чем представился клиент и какой
код он получил.

## Что в журнал намеренно не попадает

**Токен подписки.** Адрес `/api/sub/<токен>` — это и есть пропуск к VPN:
кто его знает, тот подключается. Журналы читают, пересылают и прикладывают
к обращениям в поддержку, поэтому токен вырезается ещё при записи, а не при
чтении. В журнале остаётся `/api/sub/СКРЫТО` — видно, что просили подписку,
и не видно чью.

**Заголовки `Authorization` и `Cookie`.** По первому ходит токен панели.

**Точный адрес обратившегося.** Маскируется до сети: IPv4 до `/24`, IPv6 до
`/32`. Для разбора «дошёл или не дошёл» этого достаточно, а хранить полные
адреса покупателей — то, чего политика обещает не делать.

## Как поставить

Вставить содержимое `access-log.caddy` внутрь блока домена панели, рядом с
`reverse_proxy`, и перечитать конфиг:

```sh
caddy validate --config /etc/caddy/Caddyfile
systemctl reload caddy
```

`validate` не пропустить: Caddy с негодным конфигом не поднимется, а на нём
держатся панель, приём оплаты и витрина.

## Как прочитать

```sh
deploy/subscription-agents.sh
```

Три столбца: сколько раз, какой код ответа, чем представился клиент.

- `403` у незнакомого клиента — правило ответов его не пустило;
- только `200` — правила ни при чём, дело в сети или в самом клиенте;
- пусто — запросы до панели не доходят вовсе.
