# Второй узел на машине с панелью

Узел — машина, через которую идёт трафик VPN. Панель им только управляет.

Этот документ описывает частный случай: узел ставится **на ту же машину,
где стоит панель**. Он дешевле всего (машина уже оплачена) и даёт ровно
одну вещь — запас по трафику. Чего он **не** даёт, сказано ниже, и это
стоит прочесть до установки.

---

## 1. Чего такой узел не даёт

**Живучести.** Заблокируют адрес машины — исчезнут разом VPN, панель,
кабинет, бот и приём оплаты. Второй узел заводят обычно ради обратного:
чтобы при потере одного адреса работал другой. Для этого он обязан стоять
в другом месте, у другого хостера.

**Незаметности.** Порт 443 на этой машине занят Caddy: через него идут
панель, кабинет и витрина. Узлу остаётся другой порт — у нас 8443.
Скорость от этого не меняется, но:

- сам факт соединения на нестандартный порт заметен до содержимого;
- при мягких региональных ограничениях, когда пропускают только знакомые
  порты и имена, 8443 не проходит, а 443 проходит.

Поэтому такой узел — **запасной**, а не основной. То же решение и по той
же причине описано в `docs/16-inbounds.md` для второго входа.

## 2. Чем ограничен

**Лимитом трафика машины.** Он общий на всё, что на ней работает. Сейчас
через неё идут байты — панель и бот. Узел добавит гигабайты. Превышение
остановит не VPN, а машину целиком: вместе с VPN исчезнут панель, кабинет
и приём оплаты.

Узнайте лимит тарифа **до** установки. Если он скромный, отдельная машина
за 3–5 € решает и это, и всё из первого раздела.

## 3. Установка

### 3.1. Завести узел в панели

Панель сама выдаёт `docker-compose.yml` с уже подставленным `SECRET_KEY` —
копировать надо оттуда, а не писать руками. Раздел: **Nodes → создать
узел**, затем кнопка копирования конфигурации.

`SECRET_KEY` — это пропуск к API узла. Он не попадает в репозиторий и не
пересылается в переписке.

### 3.2. Поднять контейнер

```bash
mkdir -p /opt/remnanode && cd /opt/remnanode
# сюда — docker-compose.yml, скопированный из панели
docker compose up -d
docker logs remnanode --tail 20
```

Устройство того, что выдаёт панель:

```yaml
services:
  remnanode:
    container_name: remnanode
    hostname: remnanode
    image: remnawave/node:latest
    restart: always
    network_mode: host
    environment:
      - NODE_PORT=2222
      - SECRET_KEY=<выдаёт панель>
```

`network_mode: host` обязателен: Xray должен слушать порты машины
напрямую.

### 3.3. Не открывать 2222 наружу

`NODE_PORT` — API узла, и `SECRET_KEY` к нему лежит в переменной. Панель
стоит на этой же машине, поэтому наружу порт не нужен вовсе.

Проверить, что он закрыт:

```bash
ufw status numbered | grep 2222   # ничего — значит закрыт, так и надо
```

Это единственное преимущество совмещения: связь панели с узлом не выходит
в сеть.

### 3.4. Какой адрес узла указать в панели

Здесь ловушка. Панель работает в сети Docker типа bridge, узел — в сети
машины (`network_mode: host`). **`127.0.0.1` указывать нельзя**: для
контейнера панели это он сам, а не машина.

Нужен адрес моста Docker — тот, по которому контейнер панели видит хозяина:

```bash
docker inspect remnawave --format '{{range .NetworkSettings.Networks}}{{.Gateway}}{{end}}'
```

Обычно это `172.17.0.1` или похожий. Его и указывать в поле адреса узла.

Проверить, что узел оттуда отвечает:

```bash
docker exec remnawave sh -c 'nc -z -w2 АДРЕС_МОСТА 2222 && echo открыт || echo закрыт'
```

### 3.5. Вход на 8443

443 занят, поэтому вход поднимается на 8443 — в firewall он уже разрешён.

В конфиг-профиле панели заводится инбаунд с REALITY по правилам из
`docs/16-inbounds.md`: имя прикрытия выбирается там же и по изложенным
причинам, в репозиторий не пишется.

Дальше — хост (то, что уезжает клиенту в подписку) с адресом этой машины
и портом 8443, и включение узла в отряд, иначе он не попадёт в подписки.

## 4. Проверка

Узел жив и адрес не заблокирован — рукопожатие снаружи:

```bash
openssl s_client -connect АДРЕС:8443 -servername ИМЯ_ПРИКРЫТИЯ -tls1_3 </dev/null
```

Ответ с сертификатом сайта прикрытия означает, что Xray работает.

Различать два состояния, как описано в `docs/13-vps.md`: узел жив, но пуст
— и узел мёртв. Если рукопожатие проходит, а трафик не идёт, дело не в
сети и не в ключах, а в том, что список пользователей до узла не доехал —
смотреть надо связь панели с узлом.

## 5. При смене адреса

Всё, что перечислено в `docs/13-vps.md`, действует и здесь: адрес узла
прописан не в одном месте, и забытая запись ломает не сразу, а через
сутки, когда связь с причиной уже потеряна.
