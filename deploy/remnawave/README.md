# Настройки панели

Два файла, которые нельзя восстановить из кода: они живут в панели, а не в
репозитории. Панель переустанавливается за час, эти два поля набираются
заново по памяти — и не набираются.

| Файл | Куда вставлять |
|---|---|
| `templates/xray-json-ru.json` | Шаблоны → Xray JSON |
| `response-rules.json` | Подписка → Настройки → Правила ответов |

## Шаблон: что уходит мимо туннеля

Штатный шаблон Remnawave гонит через туннель **всё**. Для России это не
просто лишний трафик: VK, Госуслуги, банки и Мах смотрят на страну входа и
показывают предупреждение либо не пускают вовсе. Человек делает
единственный доступный ему вывод — «ваш VPN сломал мне банк».

Поэтому русские адреса идут напрямую, а всё остальное — в туннель:

- `geosite:category-ru` и `geoip:ru` — списком, он обновляется сам;
- девятнадцать имён отдельно (`vk.com`, `mail.ru`, `ok.ru`, `dzen.ru`,
  `gosuslugi.ru`, `rustore.ru`, …) — списки обновляются раз в месяц, а VK
  меняет домены чаще;
- `domain:content-treasure-via.online` — наш собственный домен: панель,
  кабинет и сама подписка. Иначе клиент ходил бы за обновлением подписки
  через туннель, который эта подписка и настраивает;
- DNS русских имён спрашивается у `77.88.8.8`, остальное — у `1.1.1.1`.
  Русский резолвер на нерусском адресе выдаёт не тот CDN, и наоборот.

В `outbounds` намеренно **нет** `proxy`: панель подставляет исходящий сама,
первым в списке. Добавить его руками — значит получить два.

## Правила ответов: кто получает адреса

Правила читаются сверху вниз, срабатывает первое подошедшее. Правило с
пустыми `conditions` подходит всем — поэтому оно и последнее.

Штатный набор заканчивается правилом `Fallback Base64`, которое отдаёт
**полный список адресов** любому запросу без заголовков. То есть утёкшая
ссылка — это готовый список серверов для того, кто её нашёл: `curl` по
ней, и всё видно.

Здесь адреса получают только Happ и INCY — те два клиента, которые мы
раздаём. Остальные, включая голый `curl` и браузер, получают `403`.

Проверка после вставки:

```bash
curl -s -o /dev/null -w '%{http_code}\n' https://<домен>/api/sub/<хвост>
# 403 — закрыто

curl -s -o /dev/null -w '%{http_code}\n' -A 'Happ/1.0' \
     https://<домен>/api/sub/<хвост>
# 200 — свой клиент проходит
```

И обязательно — круговая стрелка в Happ на телефоне: `curl` проверяет
запрет, но не проверяет, что разрешение осталось рабочим.

### Чего это не закрывает

Внутри самого Happ адреса по-прежнему видны владельцу подписки: правила
решают, **кому отдать**, а не **что покажет приложение**. Это закрывается
заголовком, см. ниже.

Ссылка остаётся пропуском: кто её знает — тот подключается. Отзыв есть —
`/revoke` в боте и кнопка в кабинете, — но он ручной. Настоящее решение
следующее по очереди: короткоживущие ссылки через наш бот.

## Заголовки ответа

Подписка → Настройки → «Заголовки ответа». Это не наш код: значения живут
в панели и при переустановке набираются заново.

| Заголовок | Значение | Зачем |
|---|---|---|
| `profile-title` | `rwEncodeBase64:Gloria VPN` | подпись профиля, до 25 символов |
| `profile-update-interval` | `1` | часы; подписка подтягивается сама |
| `support-url` | ссылка на бота | значок поддержки ведёт к нам |
| `profile-web-page-url` | ссылка на бота | значок «сайт» ведёт к нам |
| `providerid` | выданный на happ-proxy.com | открывает расширенные заголовки |
| `hide-settings` | `1` | адреса не видны и не редактируются |

`rwEncodeBase64:` — не часть названия, а указание панели закодировать
значение. Кириллица и пробелы в заголовке иначе не проходят.

`hide-settings` работает **только** вместе с `providerid`: без него
заголовок молча игнорируется. Цена — ежедневный запрос приложения на
happ-proxy.com с идентификатором, хешем домена, отпечатком устройства и
системой. Хеш домена нужен им, чтобы один идентификатор не ходил по чужим
подпискам.

Заголовок применяется и к уже добавленным подпискам — переустанавливать
приложение никому не нужно, достаточно обновления по кругу.
