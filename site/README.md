# Мини-приложение

Личный кабинет покупателя: подписка, подключение, друзья, поддержка,
настройки. Открывается кнопкой в боте и из меню Telegram.

Один файл. Ни сборки, ни зависимостей, ни узла с `node_modules` на
сервере: страница целиком помещается в `index.html`, а всё, что ей нужно
от Telegram, приходит одним скриптом с `telegram.org`.

## Выложить

`git pull` **не обновляет** то, что видит покупатель. Caddy раздаёт файл с
диска, и репозиторий на сервере — просто ещё одна его копия. Пока файл не
скопирован, в Telegram остаются старые экраны, сколько ни обновляй.

```bash
cd /opt/gloria-src && git pull origin claude/multiplatform-vpn-service-ur6ef4
cp site/index.html /var/www/gloria/index.html
```

Каталог берётся из `/etc/caddy/Caddyfile` — строка `root * …` в блоке
мини-приложения. Проверить, что доехало:

```bash
grep -c "add-happ" /var/www/gloria/index.html
```

## Кеш

Telegram держит страницу мини-приложения у себя. После копирования файла
покупатель увидит новое не сразу, а вы — тем более, потому что открывали
его чаще всех.

Чтобы увидеть новое немедленно: закрыть мини-приложение **крестиком** (не
свернуть), Telegram → Настройки → Данные и память → Очистить кеш, открыть
заново.

Это же означает, что после правки нельзя судить об изменениях по своему
экрану, не сделав этого. Проверять надёжнее с сервера:

```bash
curl -s https://<адрес>/ | grep -c "add-happ"
```

## Откуда берутся данные

Страница спрашивает их у бота:

```
GET  /api/me       состояние подписки, рефералы, настройки
POST /api/trial    включить пробный период
POST /api/reissue  перевыпустить ссылку
POST /api/settings сохранить настройки
```

С каждым запросом уходит заголовок `X-Init-Data` — то, чем Telegram
удостоверяет, кто открыл приложение. Проверка этой подписи написана и
покрыта тестами (`core/atlas-telegram/src/init_data.rs`), но **самих
обработчиков ещё нет**: бот HTTP-сервером не работает.

Поэтому сейчас страница показывает придуманные числа и честно об этом
пишет полосой сверху — «показаны примерные данные». Кнопка «Добавить
ссылку» при этом потушена: отправить в клиент выдуманный адрес хуже, чем
не отправить ничего.

## Подключение к клиенту

Мастер из четырёх шагов, а не список на главной. Каждый шаг задаёт ровно
один вопрос и показывает ровно то, что нужно для ответа; всё сразу на
одном экране человек читает как «сделай всё это», а не «выбери одно».

```
Настроить VPN
  └ Где настраиваем?
      ├ На этом устройстве
      │   └ Какое приложение?   Happ | INCY
      │       ├ Установить приложение
      │       └ У меня уже есть приложение
      │           └ Ваш ключ → Добавить в приложение
      └ На другом устройстве → ключ и где взять приложение
```

Стрелка «назад» разматывает пройденный путь по стеку, а не «на шаг
раньше» по списку: к «Ваш ключ» приходят только через выбор приложения, а
к нему — только через «на этом устройстве». Переход по вкладке обнуляет
стек, иначе стрелка вернула бы в середину брошенного мастера.

Клиентов два — Happ и INCY, оба на всех платформах. Кнопка «Добавить в
приложение» — настоящая ссылка с `href`, а не переход из скрипта:
встроенный браузер Telegram скриптовый переход на чужую схему иногда
молча съедает.

```
happ://add/<адрес подписки>
incy://add/<адрес подписки>
```

В клиент едет **адрес подписки**, а не ключи. Поэтому после оплаты или
смены сервера приложение подтягивает новое само, и добавлять заново
ничего не нужно.

Форма плоская, а не `incy://crypt1/…`. Зашифрованная нужна, чтобы ссылку
не выхватывали сканеры при пересылке; здесь она и так лежит открытым
текстом двумя строками выше, на том же экране.

Если приложение не установлено, не происходит ничего — ни перехода, ни
ошибки. Поэтому рядом остаётся копирование ссылки, и на экране сказано,
почему могло не открыться.

## Тема

Тема Telegram намеренно **не** используется. Обычно мини-приложение
подстраивается под цвета клиента, но тогда у него нет своего лица — а
лицо здесь и есть отличие от соседей по ряду, у которых всё бирюзовое.
Палитра взята из значка бота (`design/render_avatar.py`), и кабинет
выглядит одинаково у всех.
