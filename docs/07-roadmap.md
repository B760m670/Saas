## Фаза 1 — «Оно работает» (цель: рабочий iOS-клиент)

**Ядро** (всё своё, без встраивания Xray/sing-box)
- [x] `atlas-types` — дескрипторы, парсер/генератор ключей всех схем
- [x] `atlas-crypto` — Ed25519 + ML-DSA-65, X25519 + ML-KEM-768, BLAKE3,
      генерация учётных данных для своих точек
- [x] `atlas-tls` — свой ClientHello с отпечатком Chrome, вычисление JA3/JA4,
      сверка с опубликованным эталоном в CI
- [x] `atlas-vless` — кодек протокола: заголовки запроса и ответа, addons, обрамление UDP
- [x] `atlas-reality` — метка REALITY поверх `atlas-tls`; обе стороны, сквозной тест,
      совместимость с Xray 26.3.27 проверена на живом захвате; окно повторов,
      которого нет даже в эталонной реализации
- [x] XTLS-Vision — паддинг против детекта TLS-in-TLS (`atlas-vless::vision`)
- [x] `atlas-transport/ws` — WebSocket: рукопожатие с браузерным набором заголовков, кадры
**Клиент TLS 1.3** — критический путь: без него соединения нет
- [x] Расписание ключей, сверено с эталонным следом RFC 8448
- [x] Слой записей: защита и снятие защиты `TLSCiphertext`, сверено с записями RFC 8448
- [x] Разбор сообщений рукопожатия и транскрипт; рукопожатие целиком
      воспроизведено по следу RFC 8448, включая собственный `Finished`
- [x] Связывание в клиент поверх сокета: конечный автомат без ввода-вывода
      плюс блокирующая обёртка; `HelloRetryRequest`, ALPS, сжатый сертификат
      (RFC 8879), смена ключей, запрос сертификата клиента
- [x] Обмен ключами `X25519MLKEM768` — порядок половин определён по живому
      захвату браузера, обе стороны обмена
- [x] Проверено на живых серверах: 19 из 20 узлов, включая российские;
      постквантовая группа работает на всей инфраструктуре яруса T1
- [x] Приёмка сертификата REALITY по общему секрету вместо цепочки:
      минимальный разбор X.509, `HMAC-SHA512` от общего секрета, плюс
      необязательная постквантовая подпись ML-DSA-65 над рукопожатием
- [x] Кривые NIST `secp256r1` и `secp384r1` — всё объявляемое умеется

- [x] `atlas-vless/session` — сессия поверх готового потока: заголовок запроса
      вместе с первой порцией данных, обрамление Vision, переход в прямой режим
      по наблюдению за внутренним рукопожатием
- [x] `atlas-dial` — сборка соединения целиком по ключу доступа:
      TCP → TLS с меткой REALITY → VLESS → адрес назначения
- [ ] `atlas-transport/xhttp` — XHTTP / gRPC
- [x] `atlas-ffi` — C ABI: разбор и описание ключа (без учётных данных),
      запуск/остановка локального прокси, счётчики; заголовок порождается
      `cbindgen` и лежит в репозитории; проверяется настоящей программой на C,
      включая сквозной проход трафика через границу
- [ ] Обёртка над C ABI для Kotlin — для Swift сделана
- [ ] `atlas-probe` — базовая разведка сети, NetworkFingerprint
- [ ] `atlas-strategy` — Thompson sampling, персистентное хранилище статистики

**Запуск**
- [x] `atlas-exit` — запускаемая точка выхода, печатает готовую ссылку
- [x] `atlas-proxy` — локальный прокси HTTP `CONNECT` на стороне клиента
- [x] Развёрнуто и проверено `curl` на живых сайтах; посторонний получает
      сайт прикрытия, что сверено с прямым соединением

**iOS**
- [x] Локальный прокси `CONNECT` как библиотека (`atlas_dial::proxy`) — старт, остановка, счётчики
- [x] Правила маршрутизации PAC (`atlas_dial::pac`) — проверяются исполнением
      в настоящем движке JavaScript, а не сравнением строк
- [x] Генерация `.mobileconfig` с payload Wi-Fi (`atlas_dial::mobileconfig`) —
      разбирается сторонним разборщиком plist; **на устройстве не проверялось**
- [x] Прокси сам отдаёт скрипт по `/proxy.pac` — правила меняются без
      переустановки профиля
- [x] `AtlasCore` — обёртка на Swift над границей C: типы вместо указателей,
      строки освобождаются сами, остановленный прокси отвечает отказом.
      **16 тестов идут на Linux**, гоняя настоящее ядро
- [x] `ProxyController` — состояние подключения вынесено из SwiftUI,
      чтобы переходы можно было проверить тестами, а не глазами
- [x] Приложение: экран, импорт ключа, ключ в связке ключей, выдача профиля
      через локальную ссылку, показ правил
- [x] CI: `ios.yml` — обёртка на Linux, сборка IPA на macOS через XcodeGen
- [ ] **Встроенный браузер** — приоритет. Без расширения это единственный
      способ пользоваться туннелем на сотовой связи; прав, профиля и Wi-Fi
      не требует
- [x] Сборка проверена в CI: `xcodebuild` собирает приложение, IPA
      выкладывается артефактом (3,1 МБ); ядро собирается под
      `aarch64-apple-ios` и симулятор
- [ ] Проверка на настоящем устройстве: приложение **собирается**, но
      ещё ни разу не **запускалось** — ни на iPhone, ни в симуляторе
- [ ] SwiftUI: одна кнопка, импорт ключа (вставка/QR/подписка), статус и метрики
- [ ] `AtlasTunnel`: `NEPacketTunnelProvider` с `proxySettings` — **отложено**.
      Требует entitlement `networkextension`, доступный только платному
      аккаунту Apple Developer. Бесплатно его даёт лишь TrollStore, а он
      работает на iOS 14.0–16.6.1 и 17.0. Вернётся в план, если устройство
      попадает в этот диапазон

**Точка выхода**
- [x] Серверная сторона TLS 1.3 (`atlas-tls::server`): выбор шифронабора и
      группы, ответная пачка, подпись Ed25519, проверка `Finished` клиента
- [x] Серверная сторона REALITY: выпуск временного сертификата с `HMAC-SHA512`
      от общего секрета, свежий ключ на каждое соединение, постквантовая
      подпись над обоими приветствиями
- [x] Сквозной круг: наш клиент ↔ наша точка выхода, включая отказ
      постороннему без единого байта ответа
- [x] Приём VLESS и проброс на адрес назначения (`atlas-vless::ServerSession`)
- [x] Проксирование посторонних на сайт прикрытия байт в байт (`atlas-exit`)
- [x] Сквозной круг по настоящим сокетам: `vless://` → туннель → назначение,
      и посторонний, видящий сайт прикрытия вместо отказа

**Инфраструктура**
- [ ] `atlas-provision`: провайдер Cloudflare Workers — деплой своей точки в один клик
- [ ] Шаблон Worker'а (VLESS over WS/XHTTP)

**CI**
- [ ] Сборка core под все триплеты
- [x] iOS-сборка `lite` в CI (IPA без подписи: её ставит тот, кто устанавливает)
- [ ] Сборка `full` с расширением и публикация `source.json` на Pages
- [x] Тест JA4-отпечатка, откалиброван по живому захвату Chromium 141

**Критерий готовности фазы:** человек с iPhone и бесплатным Apple ID ставит приложение через LiveContainer, за 2 минуты разворачивает свою точку на Cloudflare и получает работающий доступ к заблокированному сайту.

## Метрики, по которым судим об успехе

| Метрика | Цель |
|---|---|
| Время от нажатия до интернета (тёплый старт) | < 900 мс |
| Время до восстановления после блокировки точки | < 5 с |
| Доля успешных подключений в жёстко фильтруемой сети | > 95 % |
| Пик RSS в iOS Network Extension | < 25 МБ |
| Потеря скорости относительно прямого канала | < 15 % |
| JA4-отпечаток отличается от эталона Chrome | 0 случаев |
| Точек выхода, которые противник смог перечислить за месяц | < 5 % пула |
