## Фаза 1 — «Оно работает» (цель: рабочий iOS-клиент)

**Ядро**
- [ ] `atlas-types`, `atlas-crypto` (Ed25519 + ML-DSA-65, X25519 + ML-KEM-768)
- [ ] `atlas-ffi` — C ABI, генерация заголовков, Swift/Kotlin-байндинги
- [ ] `atlas-transport` — trait `Dialer` + мост к Xray-core (VLESS/REALITY/XHTTP/WS)
- [ ] Парсер и генератор ключей: `vless://`, `vmess://`, `trojan://`, `ss://`, `hy2://`, `tuic://` + подписки (base64, Clash YAML, sing-box JSON)
- [ ] `atlas-probe` — базовая разведка сети, NetworkFingerprint
- [ ] `atlas-strategy` — Thompson sampling, персистентное хранилище статистики

**iOS**
- [ ] `Atlas-lite`: локальный SOCKS5/HTTP-прокси, генерация `.mobileconfig` с PAC, встроенный браузер
- [ ] SwiftUI: одна кнопка, импорт ключа (вставка/QR/подписка), статус и метрики
- [ ] `Atlas-full`: `NEPacketTunnelProvider` (собирается, но требует TrollStore/платного аккаунта)

**Инфраструктура**
- [ ] `atlas-provision`: провайдер Cloudflare Workers — деплой своей точки в один клик
- [ ] Шаблон Worker'а (VLESS over WS/XHTTP)

**CI**
- [ ] Сборка core под все триплеты
- [ ] iOS-сборка обоих IPA + генерация и публикация `source.json` на Pages
- [ ] Тест JA4-отпечатка

**Критерий готовности фазы:** человек с iPhone и бесплатным Apple ID ставит приложение через LiveContainer, за 2 минуты разворачивает свою точку на Cloudflare и получает работающий доступ к заблокированному сайту.

## Метрики, по которым судим об успехе

| Метрика | Цель |
|---|---|
| Время от нажатия до интернета (тёплый старт) | < 900 мс |
| Время до восстановления после блокировки точки | < 5 с |
| Доля успешных подключений в жёстко фильтруемой сети | > 95 % |
| Пик RSS в iOS Network Extension | < 25 МБ |
| Потеря скорости относительно прямого канала | < 15 % |
| JA4-отпечаток отличается от эталона Chrome | 0 случаев |
| Точек выхода, которые противник смог перечислить за месяц | < 5 % пула |
