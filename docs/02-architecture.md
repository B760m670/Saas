# 02 — Архитектура ядра

Рабочее кодовое имя: **ATLAS** (*Adaptive Transport Layer & Anti-censorship System*). Имя намеренно нейтральное — слово «VPN» не должно фигурировать ни в бандле, ни в трафике, ни в названии процесса.

---

## 1. Главный архитектурный принцип

> **Мы не строим ещё один клиент к прокси-протоколу. Мы строим систему принятия решений, для которой прокси-протоколы — это взаимозаменяемые исполнительные механизмы.**

Ценность продукта не в том, что он умеет VLESS (это умеют все). Ценность в том, что он:
1. **измеряет** сеть, в которой оказался;
2. **выбирает** стратегию по измерениям, а не по настройкам пользователя;
3. **достаёт** себе рабочую точку выхода из децентрализованного каталога, устойчивого к перечислению;
4. **мигрирует** при деградации быстрее, чем пользователь заметит;
5. **учится** — локально и (анонимно, агрегированно) глобально.

Всё остальное — обвязка.

## 3. L4 — Оркестратор «Pilot». Здесь живёт вся оригинальность

### 3.1 Probe — разведка сети
При старте и при смене сети (Wi-Fi↔LTE, смена SSID, смена оператора) запускается пассивно-активная разведка за ~1.5 с:

| Тест | Что выясняет |
|---|---|
| DNS: A-запись заведомо заблокированного домена | подмена DNS оператором |
| TCP:443 к контрольным IP разных ASN | блок по IP/ASN |
| TLS ClientHello с «плохим» SNI | SNI-фильтрация и на каком этапе рвут |
| Тот же SNI, но фрагментированный | **работает ли DPI-десинхронизация** |
| UDP:443 QUIC Initial | проходит ли QUIC вообще |
| Echo через CDN-домен | жив ли CDN-фронт |
| Замер RTT/jitter/loss до 3 якорей | качество канала |
| Резолв домена из «белого списка» | признак whitelist-режима |

Результат — **NetworkFingerprint**: компактная структура (≈32 байта), которая является ключом кэша стратегий. Один раз выяснив, что «МТС, Московская обл., LTE, режут TLS на 3-м пакете, QUIC мёртв, десинхронизация работает» — мы больше не тратим 1.5 с при каждом подключении.

### 3.2 Strategy — выбор стратегии как задача о многоруком бандите

Формально: есть множество стратегий $S = \{s_1..s_n\}$ (транспорт × endpoint × параметры). Для каждой в контексте фингерпринта $f$ надо оценить полезность.

Используем **Thompson sampling с контекстом**:
- Для каждой пары (fingerprint, strategy) держим Beta-распределение $\text{Beta}(\alpha, \beta)$ по успеху коннекта.
- Отдельно — распределение по качеству (нормально-гамма по логарифму пропускной способности).
- На выборе тянем sample из каждого и берём argmax по $U = P(\text{success}) \cdot \log(1 + \text{throughput}) \cdot \text{stealth\_weight}$.
- $\alpha, \beta$ **затухают со временем** (экспоненциальное забывание, период полураспада ≈ 7 дней) — потому что противник меняет тактику, и вчерашнее знание устаревает.

Почему бандит, а не «список по приоритету»: цензура — нестационарная среда с частичной наблюдаемостью. Жёсткий приоритет либо застревает на сломанном варианте, либо перебирает всё заново каждый раз. Бандит автоматически балансирует эксплуатацию и разведку и сам находит момент, когда «старое опять заработало».

### 3.3 Happy Eyeballs для транспортов
Не пробуем последовательно. Запускаем 2–3 верхних кандидата **параллельно** со сдвигом 250 мс, побеждает первый, дошедший до полезной нагрузки. Остальные гасим. Даёт медианное время подключения < 800 мс даже при частично сломанных вариантах.

### 3.4 Router — маршрутизация
Три независимых набора правил, компилируемых в единый радиксно-доменный матчер:
- **По приложению** (Android: UID; iOS: только через профили/по домену; desktop: по процессу).
- **По домену/IP/GeoIP** (`geosite:ru-gov → direct`, `geosite:blocked → tunnel`).
- **По типу трафика** (DNS всегда через DoH в туннеле; QUIC — блокировать или туннелировать по стратегии).

**Split-tunneling по умолчанию, а не «всё в туннель».** Причины: (1) скорость, (2) банковские приложения РФ ломаются на иностранных IP, (3) **меньше объёма в туннеле — меньше внимания DPI**.

### 3.5 Health / Migrate — контроль SLA
Постоянный мониторинг: RTT, потери, эффективная полоса, доля таймаутов.
Триггеры миграции:
- пропускная способность упала ниже 30 % от скользящего медианного за 20 с → **это тротлинг**, а не «интернет тормозит»;
- 3 таймаута подряд;
- смена сетевого интерфейса.

Миграция **бесшовная**: новое соединение поднимается до разрыва старого, TCP-сессии приложений переносятся через локальный мультиплексор. Пользователь видит просадку, а не обрыв.

## 4. Ключевое решение: язык и состав ядра

### 4.1 Язык — Rust

Причины, по убыванию важности:

1. **Лимит памяти iOS Network Extension — 50 МБ** (на старых устройствах 15 МБ). Это жёсткий kill по превышению. Go-рантайм с GC в этом бюджете живёт впритык: sing-box на iOS регулярно упирается. Rust без GC даёт предсказуемое потребление 8–15 МБ.
2. Единый бинарь под все 5 платформ через C ABI, без двух разных мостов (gomobile + JNI).
3. Отсутствие GC-пауз → стабильный jitter, что важно для маскировки таймингов.
4. Безопасность памяти в коде, который парсит враждебный ввод из сети.

### 4.2 Но не переписываем всё сразу — гибридная стратегия

Писать свою реализацию REALITY с нуля на старте — **вредно**. Тонкая ошибка в паддинге или в порядке расширений uTLS = уникальный отпечаток = пользователь помечен. Проверенные реализации дороже свежих.

Поэтому:

| Фаза | Что исполняет транспорт | Что пишем сами |
|---|---|---|
| **Фаза 1** | встроенный **Xray-core** (MPL-2.0) через FFI | весь L4 Pilot, L2 control plane, L1 автопровижининг, все оболочки |
| **Фаза 2** | Xray для REALITY + **свой Rust-транспорт** для WebRTC/DoH/desync | + свой мультиплексор, свой uTLS-слой |
| **Фаза 3** | свой Rust-стек как основной, Xray как fallback | полная замена |

Так продукт работает с первого месяца, а оригинальная часть (которая и есть ценность) пишется сразу и своя.

**Xray-core, а не sing-box, для фазы 1** — потому что REALITY/XTLS-Vision там референсные, и лицензия MPL-2.0 менее вирусная, чем GPLv3 у sing-box. При этом sing-box держим как опциональный бэкенд ради Hysteria2/TUIC.

### 4.3 Состав ядра (`core/`)

```
core/
  atlas-types/       общие типы, дескрипторы, ошибки
  atlas-crypto/      Ed25519+ML-DSA-65, X25519+ML-KEM-768, HPKE, Lox-креденшелы
  atlas-probe/       разведка сети, NetworkFingerprint
  atlas-strategy/    бандит, хранилище статистики, забывание
  atlas-transport/   trait Dialer + реализации
    ├─ xray-bridge/    FFI к Xray-core
    ├─ desync/         DPI-десинхронизация (свой, с нуля)
    ├─ webrtc/         Snowflake-совместимый P2P
    ├─ dohtun/         туннель в DNS-over-HTTPS
    └─ whitelist/      туннелирование внутри разрешённого трафика
  atlas-router/       правила, geosite/geoip, матчер
  atlas-control/      клиент control plane, gossip, верификация лога
  atlas-provision/    автодеплой релеев на бесплатные тарифы
  atlas-tun/          TUN-устройство, стек (smoltcp), NAT
  atlas-ffi/          C ABI + генерация заголовков (cbindgen/uniffi)
```

## 5. Модель данных: дескриптор релея

Единица обмена во всей системе. Подписанная, самодостаточная, компактная (CBOR, ~200–400 байт).

```rust
struct RelayDescriptor {
    version:     u8,
    relay_id:    [u8; 32],        // BLAKE3 от публичного ключа
    pubkey_ed:   [u8; 32],        // Ed25519 — классическая подпись
    pubkey_pq:   Vec<u8>,         // ML-DSA-65 — постквантовая подпись
    endpoints:   Vec<Endpoint>,   // адрес + транспорт + параметры
    tier:        Tier,            // T0..T5
    capacity:    Capacity,        // заявленная полоса, лимиты квоты
    geo:         GeoHint,         // страна/ASN, без точности
    valid_from:  u64,
    valid_until: u64,             // короткий TTL: 6–24 ч
    flags:       Flags,           // udp_support, ipv6, exit_policy
    sig_ed:      [u8; 64],
    sig_pq:      Vec<u8>,
}
```

Правила:
- **Короткий TTL** — просроченный дескриптор бесполезен противнику.
- **Двойная подпись** (классика + PQ) — гибридная стойкость.
- Дескриптор **не содержит** секретов; UUID/пароль выдаётся отдельно, по защищённому каналу, персонально (см. `04-control-plane.md`).

## 6. Потоки данных

### 6.1 Холодный старт нового пользователя
```
установка → встроенный набор bootstrap-якорей (подписанные, зашитые в бинарь)
   → probe сети (1.5 с)
   → выбор канала загрузки каталога, доступного в этой сети
   → получение и верификация фрагмента Merkle-лога
   → запрос точек по Lox-креденшелу (или по инвайту)
   → бандит выбирает стратегию → happy-eyeballs → туннель
```
Целевое время «от нажатия до интернета» — **< 3 с** на первом запуске, **< 900 мс** на последующих.

### 6.2 Штатное подключение
```
кэш фингерпринта → кэш стратегии → прямой коннект → фоновая проверка каталога
```

### 6.3 Деградация
```
Health детектит тротлинг → Strategy штрафует стратегию (обновляет Beta)
   → поднимает кандидата №2 параллельно → переключение → старое гасится
```

## 7. Что считаем «сделано» для ядра

- [ ] `Dialer` — единый trait, ≥6 реализаций
- [ ] Probe даёт стабильный фингерпринт, повторяемость ≥95 %
- [ ] Бандит сходится к рабочей стратегии за ≤5 попыток в новой сети
- [ ] Миграция при тротлинге без разрыва TCP-сессий приложения
- [ ] Пик RSS в iOS NE ≤ 25 МБ при 100 Мбит/с
- [ ] Отпечаток JA4 совпадает с целевым Chrome байт-в-байт (тест на своём эхо-сервере)
- [ ] Все внешние входы фаззятся (cargo-fuzz), 0 паник
